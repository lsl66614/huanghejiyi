# 任务看板工作流

这个插件提供一个全屏看板页面和一个本地 MCP Server，两者共用同一份数据。页面归用户操作，你通过工具读写同一份数据。

## 入口

- 全局：左侧「更多」菜单 → 任务看板（占主区域，不影响当前会话）。
- 会话内：当前会话右侧应用菜单 → 任务看板（可关闭的右侧标签页，对话保持可见）。
- 当用户说「打开看板」时，调用 `open_task_board`，不要凭空描述看板内容。

## 工具

| 工具 | 用途 | 约束 |
| --- | --- | --- |
| `open_task_board` | 打开页面并返回全部任务与统计 | 只读，无参数 |
| `list_tasks` | 按 `stage` / `query` / `includeDone` 过滤读取 | 只读；回答进度问题前必须先调用 |
| `upsert_task` | 不传 `id` 新建；传 `id` 只更新给出的字段 | 返回更新后的完整看板，不必再读一次 |
| `delete_task` | 删除任务 | 仅页面可见，你无法调用 |

四个阶段：`backlog` 待开始、`doing` 进行中、`review` 待验收、`done` 已完成。
优先级：`high` 高、`normal` 中、`low` 低。截止日期用 `YYYY-MM-DD`，空字符串表示清除。

## 操作约定

1. **先读后答**：涉及「还有哪些没做完」「进度如何」「逾期了吗」时，先 `list_tasks`，用返回的 `stats` 和任务列表回答，不要凭对话记忆。
2. **一次一件事**：多个任务需要改动时，先用一条短列表说明要改哪几条、改成什么，得到用户确认后再逐条 `upsert_task`。
3. **不编造**：只增改用户明确提到的任务；标题、备注、日期不要自行补全推理内容。
4. **删除交给用户**：你无法删除任务；用户要删除时，引导他在看板卡片上点两次「删除」。
5. **状态迁移用 stage**：推进任务只改 `stage`，不要新建同名任务再删旧的。
6. 写入返回 `isError: true` 时，把返回的中文提示原样转述，不要自动重试。

## 数据位置

默认 `~/.qoder-task-board/board.json`；设置环境变量 `QODER_TASK_BOARD_DIR` 可改目录。写入是原子替换，服务进程重启后数据仍在。同一目录只应有一个 Qoder 实例在写。
