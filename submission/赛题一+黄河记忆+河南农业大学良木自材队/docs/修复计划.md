## 6. 增补（2026-11-04）：评审视角的层次化导航

> 目标（用户原话）：**让评委按层次了解项目，而不是各页面之间无逻辑乱跳转。**
> 诊断：现有跳转是"数据驱动"（谁相关跳谁），评委需要"叙事驱动"（一层层往下讲）。
> 叙事骨架即首页副标题：「从地表到展柜，四千年一层一层看清楚」——把它变成导航本身。

### 6.1 六层模型 → 四格底栏

| 层 | 名称 | 页面 | 现成语汇 |
|---|---|---|---|
| 0 | 地表 | 首页 | 印章 + 年代轴 |
| 1 | 地层 | 遗址列表 / 文物图录 | L1–L6 层号章 |
| 2 | 遗址 | DetailPage | 五格导览尺 |
| 3 | 展柜 | RelicPage | 深色区 + 剪影 |
| 4 | 档案 | 收藏/笔记/研读/网络图/导出 | 卷宗卡 |
| 5 | 流转 | 同步面板 | 双卷宗 + 冲突台账 |
| 6 | 发现 | 推荐 / 路线 | 脉络卡 |

底栏四格 = `年代(0→3 往下挖) / 档案(4) / 同步(5) / 发现(6)`，
**从左到右即评分叙事**：内容厚度 → 个人数据闭环 → 平台能力 → 拓展项。

### 6.2 对阶段 2 的微调（消解三处逻辑矛盾）

- **矛盾一「我的变杂物袋」**：网络图、导出并入「档案」（档案分段：收藏/笔记/研读/网络图，导出为页右上溢出操作）；
  第四格改名**「发现」**：只装推荐 + 路线（"接下来看什么"），版权收进页脚。
- **矛盾二「同步是属性却成目的地」**：同步 tab 加**角标**（冲突数/未同步数），平时也有信息量；
  首页/档案的 SyncStatusBar 承担"属性常驻"，tab 承担"可演示证据"，两者不重复。
- **矛盾三「档案主语不稳」**：档案页头**常驻显示当前身份**（设备 A/B）+ 一句"在同步页切换"，把跨 tab 耦合显式化。
- **取舍声明（须写进 PPT/文档）**：新底栏按**赛题条款权重**分层，不是按用户任务分层——
  这是提交前 2 天约束下的自觉取舍，不是天然最优解。

### 6.3 新增第 6 个公共件：`StratumCrumb`（层位面包屑）

| 页 | 面包屑 |
|---|---|
| 首页 | 无（本身是地表） |
| 列表/图录 | 地表 › 仰韶 L1 |
| 详情 | 地表 › 仰韶 L1 › 班村遗址 |
| 展柜 | 地表 › 仰韶 L1 › 班村遗址 › 蚌塑龙虎 |

- 复用 `LayerBadge` 词汇（层色点 + 层号），一行文字；
- **唯一父级规则**：每页定义一个"上"，返回键永远回父级不回"刚才"；
- **横向跳转必须贴标签**（"共出器物""同年代推荐"式），散边如 `NetworkPage:617` 跳同步，
  随网络图并入档案页自动消解。

### 6.4 可选加分项（阶段 3 之后，时间不够先砍）

用现成 `routes.json` 引擎加一条**「评审导览」路线**：班村(五层级) → 大河村(实拍+收藏) → … → 终点 CTA 指向档案/同步，
让评委不依赖讲解自己走一遍故事。成本约半天。

- [ ] 档案页头显示当前身份；同步 tab 有角标。
