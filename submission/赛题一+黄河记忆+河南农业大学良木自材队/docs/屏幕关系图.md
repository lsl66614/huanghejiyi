## 一、总纲（一句话）

**19 个屏不是 19 个页面，是同一份语料 × 同一份个人数据的 19 种投影。**
缝合剂是 `target_key`（`site:{id}` / `relic:{id}` / 五段 section / `notebook:inbox`）——
所有个人数据都挂在语料实体上，所以任何两个"看起来无关"的屏，共享同一批挂载点。

## 二、三层数据结构

```
┌ 语料层（只读）  rawfile/sites/*.json（42 遗址 + 104 文物）
│                 └→ ContentRepo（缓存单例）→ 15 个屏
├ 个人数据层（读写） RDB 六表
│    favorite / note / note_tag / favorite_tag / progress   ← 进同步域
│    visit（本地，不同步）                                    ← 喂推荐加权
│                 └→ UserDataRepo → 12 个屏
└ 元层  SyncStatus（全局快照）· AttributionRepo（101 条署名）· RouteRepo（7 条线）
```

**挂载语法是全站通用货币**：笔记可挂遗址/单件文物/遗址某一段；收藏同时接受两种实体；
进度挂在 `(target_key, section)`。这是"双实体"赛题条款在数据结构层的落点。

## 三、导航拓扑（现状）

### 3.1 三层空间模型，两套机制

| 层 | 页面 | 进入方式 | 栈行为 |
|---|---|---|---|
| **频道层**（4 格） | 年代 Index / 收藏 FavoritesPage / 笔记 NoteCenterPage / 我的 MinePage | `switchToTab()` | `clear + replaceUrl`，栈深恒 1，不挂返回键 |
| **内容层** | ListPage / RelicListPage / RouteListPage / RoutePage / SearchPage / RecommendPage / NetworkPage / SyncPage / RecyclePage / ExportPage / CreditsPage | `pushUrl` | 压栈，返回逐级退 |
| **叶子层** | DetailPage / RelicPage / NotePage / TargetPickerPage | `pushUrl` | 终点页，不挂底栏 |

硬规则（`AppNavBar.ets` 注释）：频道页只能走 `switchToTab`，
谁 `pushUrl` 频道页，栈里就留残影，返回键与底栏变成两套矛盾语法。
`ListPage` 曾挂 `AppNavBar(active:0)` 造成双导航，已摘（注释留档）。

## 四、五种内在联系（边类型学）

| 类型 | 例子 | 语义 |
|---|---|---|
| **下钻** | 地表→地层→遗址→展柜 | 发掘动线；返回键应逐级重放 |
| **回流** | 展柜→所属遗址；推荐→详情 | 双实体互查 |
| **派生** | 收藏+标签→网络图；visit→推荐；progress→六格条/五格尺/路线完成度 | 个人数据长出的第二层信息 |
| **同步** | 六表→MergeEngine→冲突台账；SyncStatus→首页/我的状态条 | 同一份裁决的两种呈现（属性常驻+面板可演示） |
| **元数据** | Attribution→版权页+灯箱逐张署名；ImagePolicy `real_`→全站图位 | 诚实体系的执行链 |

## 五、三条贯穿每一屏的隐形主线

1. **年代主线**：`eraColor`/L1–L6 以不同形态出现在每一屏——卡脊、层号章、chips 色点、
   导览尺、网络图节点色、推荐"同年代"理由。同一语义，从不裸色（块面/浅底/深底三套令牌）。
2. **双实体主线**：site/relic 同构贯穿收藏、笔记、进度、推荐、网络图、搜索、导出——
   文物不是遗址的附件，是平级公民。
3. **诚实主线**：`real_` 才上屏；缺图走材质线稿并标"待入藏"；每张实拍在灯箱与版权页双重署名；
   AI 图仅限首页 6 张年代封面。

## 六、当前拓扑的三个断裂（修复计划对症处）

| 断裂 | 表现 | 治法（见修复计划） |
|---|---|---|
| 流转层是孤岛 | SyncPage 入边 2、出边 0，却吃 3 条赛题条款 | 升为底栏第 3 格 + 角标常驻 |
| 派生主线断头 | progress 六表齐全地写着，全局视图（剖面完整度）被删 | 档案页「研读」分段重建 |
| 双实体一条腿寄居 | 文物线挂在账号页第 03 行 | 首页「遗址⇄文物」分段 |

## 七、目标结构（修复计划 §6 落地后）

```
底栏：年代(0→3 往下挖) / 档案(收藏·笔记·研读·网络图·导出) / 同步(流转) / 发现(推荐·路线)
每屏回答：我在第几层（StratumCrumb 面包屑）、我的父级是谁（返回键唯一语义）、
          横向跳转为何发生（贴标签："共出器物""同年代推荐"）
```

一句话收束：**语料给骨架，挂载点给归属，年代色给坐标，同步给流动性，
provenance 给来历（升级中），层位线给承继（规划）**。
