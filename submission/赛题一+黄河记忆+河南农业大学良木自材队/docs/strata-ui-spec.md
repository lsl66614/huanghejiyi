# 方案 G「展陈白盒」—— 全 App 视觉翻新实施规范

> 状态：2026-10-12 定稿。本文件是**画稿定向 spec + ZCode 实现清单**。
> 前身方案 C「地层·发掘深度」全文留在 `strata-ui-spec.plan-c.bak.md`，未删除。
> 本方案替换 C 的**色底与材质**，保留 C 的**信息架构与组件语义**（见 §1.3）。
>
> 校准来源：高保真 UI 展示渲染参考图（Google Arts & Culture 式双机 hero shot）。
> 从那份参考里只取**能落到工程上**的三件事：白盒底、满幅图、胶囊按钮；
> 参考图里属于「效果图语法」的部分（无颗粒、铬边高光、明暗模式对比）**明确不取**，
> 理由见 §9——本项目要的是能跑的界面，不是打光完美的假手机。

## 0. 一句话世界观

> 黄河记忆从「向下挖的档案馆」改为「一座灯打得匀的展厅」：
> **墙是白的，画是满的，字是少的。**

前身方案 C 的地层隐喻**不被推翻**——它降级为**展厅的导览系统**：
地层色仍在，但只作为「展签色标」出现在图与文字之间，不再是整个界面的底色。
博物馆的真实做法正是如此：展厅是白的，年代信息在展签上。

## 1. 设计原则（写代码前先读，这四条决定后面所有取舍）

### 1.1 白盒：界面不抢图

底色从纸色 `#F5F1E8` 提到近白 `#FBFAF8`，卡面提到纯白 `#FFFFFF`。
**唯一目的是让照片成为画面上最饱和的东西。** 参考图里最抓人的是满幅面具大图，
面具之所以跳出来，是因为它周围全是白的。纸色底会和照片在暖调上互相打架。

### 1.2 字的层级从「颜色」改成「大小 + 字重」

参考图里正文段落和标题都是深色，靠**字号差**拉开层级，不靠灰色。
本版同步收窄灰色层级的使用：`SUB` 只用于真正的辅助信息（计数、时间戳、单位），
**不再用于「想让文字看起来轻一点」**。这一点直接决定 §7 的适老门禁能否守住。

### 1.3 保留 C 的骨架，只换皮肤

C 方案的五个组件**继续实施，语义不变**，只是配色与材质改按本规范：

| C 组件 | 在本版中的角色 | 变化 |
|---|---|---|
| `StrataSpineCard` | 内容卡 | 卡面改纯白；8vp 层色脊**保留**（这是「展签色标」） |
| `LayerBadge` | 层号章 | 白底 + 发丝描边 + 层色圆点，取代 C 的层色实底 |
| `StrataProfile` | 剖面条 | 保留，但下沉为 Index 的第二眼信息（见 §5.1） |
| `DepthRuler` | 深度尺 | 保留，在 Detail/Mine 使用 |
| `VerticalEraText` | 竖排层名 | **本版禁用**（§9：竖排是 C 的纸面语汇，白盒里读起来像装饰） |

### 1.4 满幅图，但图必须是真的

参考图的力量 100% 来自「满幅高清实体图」。本项目当前**图像存量不支持这条**：

| 范围 | 有实拍 | 总数 | 结论 |
|---|---|---|---|
| 遗址 | 11 | 42 | **74% 走占位** |
| 文物 | 0 | 104 | **100% 走占位** |

`common/ImagePolicy.ets` 现行口径（只渲染 `real_` 前缀）**本版不放开**（§9）。
因此本规范分两条轨道实施：

- **轨道 A（现在就能做）**：白盒化 + 排版重构 + 占位态重设计（§6）。不依赖新照片。
- **轨道 B（照片到位后）**：满幅头图 + 图集 + 灯箱（§5.3）。逐张照片就位逐张启用。

**禁止**为了让界面"看起来做完了"而用 AI 图填充真实图位。

### 2.4 图上的文字：scrim 是新引入的机制，必须按实测值用

参考图里白字直接压在照片上。本项目的照片**明度不可控**（Commons 来的实拍，
有白墙、有天空、有雪）。因此规定：**任何压在照片上的文字，必须先铺 scrim。**

`scrim = #141210`（即新 `INK`）按 alpha 合成，实测最坏情况＝照片纯白 `#FFFFFF`：

| 用途 | 最低 alpha | 合成后底色 | 白字实测 |
|---|---|---|---|
| 头图主标题 / 正文 | **0.60** | `#727170` | 4.87 |
| 「示意图」角标（9pt 小字） | **0.70** | `#5B5958` | 6.97 |
| 底部渐变 scrim 实端 | **0.68** | `#5F5E5C` | 6.48 |

> 三档都是**下限**，不是推荐值。渐变 scrim 从 `0` 线性升到实端值，
> 文字只允许落在 ≥ 上表阈值的那一段里——**这条须写进代码注释**，
> 否则后来的人会自然地把渐变拉长、把文字推上去，然后静默跌到 3:1。

## 3. 全局制式

1. **白盒区（全站默认）**：页底 `#FBFAF8`，卡面纯白，层级靠 `LINE_HAIR` 发丝 + 阴影。
2. **深色区（仅一处）**：`RelicPage` 展柜（§3.1 勘误——灯箱与关系图画布实为浅色）。
   参考图的明暗对比在本项目就落在这一处（§5.4）。
3. **阴影**：白盒体系需要阴影建立层级（纸底靠底色差，白盒不行）。沿用既有
   `SHADOW_CARD_*` 参数，但**浅色卡片的阴影 alpha 要减半**——
   `#1A2B2622` 在原纸底上刚好，纯白底上会显脏，改用 `SHADOW_CARD_COLOR_LIGHT`。
   浮层阴影 `SHADOW_MODAL_*` 不变。
4. **圆角**：卡片 `RADIUS_MD 8` 不变；胶囊走新 `CAPSULE_RADIUS 24`。
   **注意** `RADIUS_PILL = 190` 是既有值、为关系图大圆定的，**不要**拿它当胶囊用。
5. **字体**：三族不变（`FONT_SERIF` 宋 800 单面 / `FONT_SANS` 系统黑体 / `FONT_MONO`）。
   **白盒体系下宋体用量要减**：参考图通篇无衬线，宋体在本版只保留给
   ① 页面主标题（`FS_DISPLAY`）② 节标题（`FS_SECTION`）③ 遗址/文物名。
   正文、按钮、标签全部落 `FONT_SANS`。
6. **间距**：档位不变（0/1/3/4/6/8/10/12/16/24/32/40/80），
   `lint_visual_consistency` 继续守。
7. **按压**：见 §4.2——本 SDK 的 `stateStyles` 按下态不生效，必须手写。
8. **切换器的层级（2026-11-04 增补，实现前必读）**——「谁换页面、谁换视图、谁筛数据」
   必须用三种不同语法分开，否则同一屏三排「黑底选中胶囊」会被读成三排同类控件。

   | 层 | 语义 | 组件 | 视觉语法 |
   |---|---|---|---|
   | L1 | 全局频道（跨页面） | `AppNavBar` | 图标 + 文字，底部四格 |
   | L2 | 页内目的地（换整块内容） | **`UnderlineTabs`** | 不带盒子；选中＝INK 字 + 3vp INK 下划线，全宽均分，贴页头下沿，整行下沿一条发丝 |
   | L3 | 数据筛选（看哪些） | 胶囊 chips（`INK` 实底选中） | 高 32，横滑，带「筛选」眉标 |
   | L4 | 视图切换（怎么看，同一份数据） | `SegmentTab` | 高 32，**必须与 L3 分开或加「视图」眉标**；同排有其他控件时用 `compact`（28 高 / 11pt） |

   **依据**：
   - Segmented control 的正确定位是「同一份数据换一种展示」（2–5 个互斥项）；
     用于页面级模式切换或导航是典型误用
     （"navigation disguised as view switching"）——
     <https://www.letsgroto.com/blog/segmented-control-ui>
   - Material 主页签放在内容区顶部、顶栏正下方，表达主要目的地；
     嵌套层才用 secondary tab bar —— <https://m3.material.io/components/tab-bar/overview>

   **实测教训（2026-11-04）**：首页「遗址 / 文物」与档案页「收藏 / 笔记 / 研读 / 网络图」
   原本都是居中胶囊，与下面的筛选胶囊长得一样；档案页因此叠了四层控件，
   第一张收藏卡被压到整屏 57% 处。改页签 + 折行后层数降到三层，
   首卡上移约 105px。

### 3.1 「深色区」的真实范围（勘误，实现前必读）

初稿把深色区写成「RelicPage 展柜 + 灯箱」，**这是错的**。实测：

- `RelicPage.ets` 确实全篇走 `ON_DARK_*` 族（`ON_DARK_BG/PANEL/TEXT_ALT/SUB/GOLD/LINE`），
  是真正的深色区，且它**已经在用 `ON_DARK_GOLD` 做交互色**（收藏按钮的底与描边），
  而不是 `ACCENT`。
- `ImageViewer.ets` 的「深色遮罩」注释写"深色"，实际底色是 `SURFACE_VIEWER`——
  **是浅色**（`#EFECE7`），并配合 `SURFACE_RAISED`。它是浅色浮层，不是深色灯箱。
- `NetworkPage.ets` 的画布底是 `THEME_BG`（＝`SURFACE_PAGE`）——**也是浅色**。

因此：

| 区域 | 真实底色 | 本版处理 |
|---|---|---|
| RelicPage | 深（`ON_DARK_*`） | 按 §2.2 换值；交互色继续 `ON_DARK_GOLD`/新增 `ON_DARK_ACCENT` |
| ImageViewer | **浅**（`SURFACE_VIEWER`） | 按 §2.1 换值；**不要**误改成深底 |
| NetworkPage 画布 | **浅**（`THEME_BG`） | §5.9 的"关系图画布是深底"**作废**，节点色用既有 `ERA_COLORS` 即可 |

> 影响 §5.9：NetworkPage 在浅色画布上，节点点色用 `eraColor()`（原块色）是**正确的**，
> 无需换 `ERA_TEXT_DARK`。`ERA_TEXT_DARK` 在本版只有 RelicPage 一个真实使用点。
> 这条勘误同时说明：**改任何颜色前先 grep 该页实际用的令牌**，
> 不要凭"页面名字看起来应该是深色"推断。

## 4. 交互与动效

### 4.1 光标语言随材质改

参考图的界面没有边框，圆角中等，按钮是**胶囊**。本版关键动作位从
「描边矩形」改「胶囊」：

| 位点 | C | 本版 |
|---|---|---|
| 主按钮（"存档"等） | 赭红实心矩形 | **胶囊**；落在深色头图上时用白底黑字（参考图 `Take a virtual tour` 的做法），落在白盒底上时用 `ACCENT` 实底白字 |
| 次按钮 | 描边矩形 | 发丝描边胶囊 |
| 筛选 chip | 矩形选中底 | 胶囊（选中＝`INK` 实底白字） |
| 标签 | `RADIUS_SM` 小方角 | 不变（标签与按钮要能分辨） |

主按钮的填充要跟着它落的位置走：**深色头图上用白底黑字**最容易出效果，
但它要求头图已就位（轨道 B）；头图未就位时白底会失去对比对象，改用
`ACCENT` 实心胶囊（如 NotePage「存档」）。

### 4.2 按压反馈：全部手写，不要留给 stateStyles

已核实：本 SDK 的 `stateStyles` 按下态抓不到（`lint_motion` 会过，运行时无反馈）。
实测全站 **10 个页面共 56 处 `stateStyles`**，而**只有 `Index.ets` 有 1 处 `onTouch`**：

| 页面 | stateStyles | onTouch |
|---|---|---|
| DetailPage | 12 | 0 |
| FavoritesPage | 10 | 0 |
| ListPage | 9 | 0 |
| NotePage | 7 | 0 |
| SyncPage | 6 | 0 |
| NetworkPage | 3 | 0 |
| RelicPage | 3 | 0 |
| Index | 2 | **1** |
| MinePage | 2 | 0 |
| RecommendPage | 2 | 0 |

**这 56 处按下态当前全是死的。** 本版要求逐页迁移为手写
`@State pressed + onTouch`（三档：Down 置位 / Up 与 Cancel 清位），并配 `pressAnim()`。
这是**已存在的缺陷**，不是本版引入的，但白盒体系的按钮没有边框兜底，
死按下态会比纸色底更明显，故一并修。

> 迁移时注意 `lint_motion` 规则 6 只认两种逐字内联形态
> （`{ pressed: { scale: { x: PRESS_SCALE, y: PRESS_SCALE } } }` /
> `{ pressed: { opacity: PRESS_OPACITY } }`）。手写 `onTouch` 会移除 `stateStyles`，
> 从而绕过规则 6——**这是规则覆盖上的一个缺口**，迁移完后
> 应给 `lint_motion` 补一条"`onClick` 宿主若无 `stateStyles` 则须有 `onTouch`"的反向检查，
> 否则按下态会从"死了"变成"没人检查"。

### 4.3 转场：回到横移 + 淡入

取消 C 的「下钻」。每个 `@Entry` 页保持既有四件套（`lint_motion` 规则 4 逐字校验）：

```
pageTransition(): void {
  PageTransitionEnter({ duration: durRouteIn(), curve: curveOut() })
    .translate({ x: ROUTE_SHIFT_VP, y: 0 })
    .opacity(ROUTE_FADE_MIN);
  PageTransitionExit({ duration: durRouteOut(), curve: curveIn() })
    .translate({ x: ROUTE_SHIFT_VP, y: 0 })
    .opacity(ROUTE_FADE_MIN);
}
```

滚动揭示沿用 `RevealOnScroll`（18vp 升起）。白盒体系下 `REVEAL_SHIFT_VP`
可减到 12——参考图那种静态展陈感不要太多位移。**这是唯一允许的动效数值变更**，
改则须同步 `lint_motion`。

### 4.4 满幅头图的视差：不做

参考图是静态图，没有滚动视差信息。且视差在长列表上是耗电与眩晕来源
（`Motion.ets` 已有减弱动画支持，但没有视差）。**明确不做。**

## 6. 占位态重设计（轨道 A 的核心交付）

因为 74% 遗址 / 100% 文物走占位，**占位态在本项目不是边角，是主画面**。
C 方案对占位只有一句「年代色整块」，白盒体系下必须重做成能看的东西：

| 占位 | 构成 |
|---|---|
| 遗址头图位 | 层色整块（满幅 320）+ 居中 `FS_TITLE`「图像整备中」`ON_DARK_TEXT` + 下方 `FS_CAPTION` mono「待实拍入仓」+ 角标位预留 |
| 卡片封面位 | 层色整块 3:2 + `FS_CAPTION`「图像整备中」 |
| 文物图位 | 单色剪影（既有 `SilhouettePlate`）+「待入藏」+ 出土层层号章 |
| 空列表 | 层色点 + `FS_TITLE` 一句话（各页文案见 §5） |

## 7. 可读性与适老（本版最大风险，须优先回归）

白盒 + 无衬线 + 满幅图这套语言，天然会和本项目的两道门禁顶牛：

| 门禁 | 风险 | 本版对策 |
|---|---|---|
| `lint_aging` 正文 ≥ 12pt、行高 ≥ 1.3× | 参考图正文视觉上偏小（约 13–14pt 相对屏宽） | `FS_BODY` 14pt **不动**，`LH_BODY` 22 不动。**不得**为"像参考图"而调小 |
| 长段落可读性 | 白底黑字大段落比纸底更容易显得生硬、行太长 | 正文行宽上限保留既有 `PAGE_PAD_X 24`；**不增大**字号，改为控制行宽 |
| `check_contrast` 36 项 | 换底色会让全部项重算 | §2 全部实算过（见 §8） |

另外三条白盒特有问题：

1. **纯白卡面 + 近白页底**必须有阴影或发丝，否则卡片消失。
   两者择一，不要都给（给全了显脏）。
2. **宋体在大字号下仍然要 800 面**（`WT_SERIF`）——白盒底上没有纸色的暖调遮掩，
   合成加粗的糊边会非常明显。
3. **展柜（RelicPage）与白盒区切换时的亮度冲击**：进出灯箱要有
   `DURATION_BASE 240` 的过渡，不要瞬切。（灯箱本身是浅底浮层，
   真正需要过渡的是 RelicPage 的深底进出。）

## 8. 门禁回归清单（每页做完必须全跑）

七道门禁全部沿用，**没有任何一项被豁免**：

```bash
python tools/check_contrast.py          # 36 项，本版需重算（新令牌见 §2）
python tools/lint_aging.py              # 正文档位
python tools/lint_a11y.py               # 读屏标签（白盒改文案后须重跑）
python tools/lint_motion.py             # 转场四件套 + 按压
python tools/lint_tokens.py             # 裸值
python tools/lint_visual_consistency.py # 间距档位
python tools/check_font_pairing.py      # 字重×字族
python tools/validate_sites.py <dir>    # 内容（本版不动内容）
```

`check_contrast.py` 直读 `common/*.ets` 源码，所以**改令牌即改门禁输入**，
不需要同步改脚本；但以下三组值**必须新增检查项**——
否则它们会落在门禁之外，这正是本版最容易漏掉的地方：

1. `ERA_TEXT_DARK × {ON_DARK_PANEL, ON_DARK_RAISED}`（6 项）；
2. `ON_DARK_ACCENT @ ON_DARK_PANEL`（1 项）；
3. scrim 三档（用脚本既有的 `composite()`，以 `#FFFFFF` 为最坏底算出合成色，
   再校验白字）。

模拟器侧（既有手法，见 `docs/PITFALLS.md`）：

- `hdc dumpLayout` 核对满幅头图下压字的 bounds 不越界；
- 截屏 + PIL 像素采样验证白盒底色确实变了。**注意容差**：
  `#F5F1E8` 与 `#FBFAF8` 只差 6 个色阶，容差给大了会测不出变化。

## 9. 明确不做（含理由，避免后来者"顺手补上"）

| 不做 | 理由 |
|---|---|
| **伪深色模式** | `resources/dark` 只有一个启动色，`EntryAbility` 显式锁浅色。做展示图时合成一个不存在的深色界面＝拿虚构状态当截图，与 `IMAGES.md` 的诚实口径直接冲突 |
| **放开 AI 图填真实图位** | `IMAGES.md` 2026-10-03 定稿：AI 图仅限首页 6 张年代封面。这是学术诚实问题，不是审美偏好——考古/文物影像必须是实拍 |
| **无颗粒 / 铬边高光 / 均匀自发光** | 这是参考图的"效果图语法"，描述的是渲染而非界面。真机截图套外框即可，不需要打光完美的假手机 |
| **把浅色区改成深底**（ImageViewer / NetworkPage） | 实测这两处底色是浅的（§3.1）。"灯箱应该是黑的"是直觉不是事实，改之前先 grep 令牌 |
| **竖排层名 `VerticalEraText`** | C 的纸面语汇。白盒里竖排宋体读作装饰，且需要额外的读屏修正（a11y 成本） |
| **视差滚动** | 耗电 + 眩晕，`Motion.ets` 无对应支持 |
| **改数据模型 / 同步域** | 学习进度仍是 `ProgressDO`，深度/层号只是它的视觉表达（沿用 C 口径） |
| **改 6 个年代色值** | 已锁。周/宋相近的问题靠「脊色 + 层号章 + 深底提亮变体」三重编码区分 |
| **iOS 状态栏 / 底部 tab 语法** | 本 App 是 `deviceTypes: ["default"]` 的 OpenHarmony API 26 应用，展示图挂 iOS 外壳是自伤 |
