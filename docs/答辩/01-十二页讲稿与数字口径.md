## S6 LWW 裁决（技术高点）

**屏上**：三条规则 + 右侧实测读数卡「采信 deviceB 10:46:14 / 落选 deviceA 10:45:30」。

**三条规则照着念**：
1. 双方都有同一条 → 取 `updateTime` 大者；**完全平局按 `deviceId` 字典序**（确定性，不靠运气）。
2. 只有一方有 → 直接纳入。一方是墓碑（`isDeleted=1`）而对方存活时，**仍按时间戳裁决**——删除本身就是一次编辑。
3. 输出 → 终态回写；时间戳不同即记入冲突历史（**保留败方快照**，上限 50 条滚动）；刷新 `lastSyncTime`。

**主动交代那次翻车**（这句一定要说，主动比被动好）：
> 这页还想交代一个我们修过的错：`note_tag` / `favorite_tag` / `tag` 三张关联表原本没有 `deviceId` 列。平局时两个空串比较恒为假，等于「远端恒赢」，而日志还写着 `tie_break_deviceId`，规则名不副实。补列并原位迁移后，三张表与其它表走同一套决胜。

**追问**：「LWW 有什么毛病？」
> 两个本机致因已修：时钟回拨、同毫秒连写。用单调逻辑时钟，`now = 墙钟 > 高水位 ? 墙钟 : 高水位 + 1`，高水位持久化在 `sync_meta.lastWrite`。
> 但**跨设备绝对时钟偏差修不了** —— A 的墙钟快一分钟，A 就稳赢。这靠系统 NTP 兜底，应用层不做跨设备逻辑时钟。这是已知限制，`LogicalClock.ets` 文件头写明。

**追问**：「这算分布式吗？」
> 传输层是可替换适配器，真机走官方分布式 RDB：六张表注册 + `remoteQuery` 拉取 + `SYNC_MODE_PUSH` 推送，经软总线走设备间加密通道。代码在包里可查。

## S7 双轨演示（口径最强的一页）

**屏上两列**：单机双档案仿真 / 真机分布式；底部强调带「两轨共用同一个 MergeEngine，也共用同一个 SyncPanel」。

**左列（仿真）**：
- 设备 A（手机）/ B（平板）各持一个**独立 RDBStore**（`huanghe_memory.db.sim.deviceA/B`）
- 在 A 身份写的笔记，B 看不到 —— **是真分离，不是同一个库贴标签**
- 点「组网同步」→ 分批 yield 驱动进度 → 方向连线、百分比、最后同步时间、冲突数逐屏出现
- 不依赖第二台设备，现场丢设备也能完整演示

**右列（真机）**：
- 六张同步表整体注册为分布式表，软总线发现可信组网设备
- **先 `remoteQuery` 拉快照 → 同一 MergeEngine 裁决落库 → 最后 PUSH 推终态**
- **顺序不能反**：先推会让本机旧值覆盖对端较新的行，等再拉时冲突已被抹平
- 监听网络可用事件，恢复后自动跑一次合并（30 秒冷却去抖、失败只记日志不打断用户）

**追问**：「是不是两套逻辑？」
> 不是。两轨共用同一个 `MergeEngine` 和同一个 `SyncPanel`，换的只是传输层实现。`ITransport` 只有两个方法：`exchange` 和 `notifyAfterSync`。

**追问**：「自动同步为什么仿真模式不开？」
> 仿真模式没有对端设备，自动跑它没意义。掉线恢复的自动补同步只在真机模式开。

## S10 门禁与实机走查

**屏上三张卡**：13/13 门禁全绿 · **23.62** MiB signed HAP · **零** INTERNET 权限；下方 T9/T11/T24/T25 四条人眼复核。

**讲 1 分钟**：
> 十三道门禁挡在出包之前 —— `build-oh.bat` 在 `assembleHap` 之前调用，任一非 0 直接阻断出包。兜的是 schema、署名、对比度 58 项、字号适老化、读屏标签、动效、令牌裸值、跨页间距、字重字族、tsbuild、单测。

**零 INTERNET 是全场最硬的证据**（务必讲）：
> 离线不是「飞一次行模式」—— `module.json5` **只声明两条权限**：`DISTRIBUTED_DATASYNC` 和 `GET_NETWORK_INFO`，**没有 `INTERNET`**，系统层就发不出 HTTP 请求。网络 API 全仓只剩一处 `createNetConnection()`，它只订阅「网络恢复」事件来决定何时合并，不搬运任何数据。

**追问**：「门禁能证明什么？证明不了什么？」
> 门禁只能证明**写法合法**（schema、对比度、令牌、字号、无障碍、动效），**证明不了屏上真有反应**。所以交互类另有实测脚本兜底：按压反馈逐像素比对、冲突同步七步带读数。

**追问**：「23.62 怎么算的？」
> 签名 HAP 实测 24,764,369 B = 23.62 MiB，限 40 MB。构成：rawfile 20.34 + `modules.abc` 2.16 + debug 符号表 0.85。脏条目 0，直接从签名包内清点。
